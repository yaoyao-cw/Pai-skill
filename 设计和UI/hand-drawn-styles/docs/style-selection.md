# 如何选择画风

选型说明帮助缩小候选；完整配方、参数、别名、参考图和生成合同仍以 `STYLES.md`、协议及渲染器为准。说明不会加入生成 prompt，也不会修改参考图或 workflow。

## 查询与使用

```bash
python3 -B scripts/render_prompt.py --catalog
python3 -B scripts/render_prompt.py --list
```

`--catalog` 返回原菜单字段加 `guidance`，必须单独使用，不可与 `--list`、`--style`、`--subject`、`--format` 等参数混用。查询只读取本地文本，不加载或下载图片；即使图片缓存为空且离线也可使用。旧 `--list` 的结构和行为保持不变。

选型元数据来自包内 `catalog/style-guidance.json`：

- `suitable_for` 是编辑建议，不是用户实验结论。
- `selection_cues` 是有配方章节来源的识别差异，不是可复制进 prompt 的新指令。
- `limitations.kind=recipe-constraint` 是原配方约束；`selection-advice` 是选型建议，不能扩大成生成禁令。
- `related_styles` 说明相近编号的区别，名称等基础信息仍从原菜单读取。
- `evidence` 同时记录结论类型、适用范围和来源，不能只看类型忽略范围。

元数据只在目录查询、安装和打包检查时加载。损坏或缺失会使这些检查失败；普通显式画风调用不会读取它，不应因此失效。新增或删除画风时须同步选型数据，但不得把它变成第二份配方真源。

容易混淆的三组画风及三个历史失败原因见 [画风对照](style-comparison.md)。同页还记录了尚未执行的小规模同题实验，不能当成新的视觉验证结论。

## 五个固定情境的协议演练

这是人工核对的预期交互，不是自动测试证明 Agent 必然遵循。

| 用户输入 | 预期路由 | 不能做什么 |
| --- | --- | --- |
| “用 20 号画两个孩子一起搬坐垫” | 已明确编号，直接采用 20，完整使用其正式合同 | 不重新要求从候选中选；不把选择说明替换成 prompt |
| “帮我画一张手绘图” | 缺乏足够用途和视觉意图，展示完整菜单并等待选择 | 不凭偏好猜一个画风；不编造匹配分数 |
| “家庭蜡笔画，爸爸陪孩子看书” | 命中已有家庭蜡笔直接映射，采用 3.1 | 不退回泛化候选；不把纸页摄影感塞进 3.1 |
| “用图解释三个工作步骤，风格没想好” | 提供 1 和 4 两个候选，说明网格细线与竖向黑豆人的区别及文字/场景限制，等待选择 | 不自动选择；不推荐仅讲单动作的 20 来冒充多步骤版式 |
| “完整山村风景，但视觉要极简，编号未定” | 先说明完整环境与 19/20 的禁背景约束冲突；可比较 3 的简化环境、12 的满幅场景档，说明取舍后等待选择 | 不声称任一候选同时满足完整景物细节和大幅空白单动作；若用户明确指定 19/20，则指出冲突并讨论，不静默换风格 |

没有指定画风但用途与视觉意图足够明确时，最多先列 2–3 个有依据的候选；每项说明匹配原因和重要限制，保留完整菜单入口，等待用户选择。依据不足时直接展示完整菜单。显式编号、名称、别名及已有家庭语义映射始终优先。

## 来源与可追溯性

元数据的 `sources` 使用仓库相对路径、章节和 `availability`：

- `runtime`：运行包内必须存在的来源，例如 `STYLES.md` 的 `style:14` 章节。
- `repository`：供维护者回到源码仓库核对的资料指针。轻量包无需包含这些文件；它们缺席不表示运行依赖缺失。包内已有上表摘要。

源码仓库中的详细定位如下（这些路径不保证在轻量安装目录内存在）：

- `examples/README.md`：各编号样例登记。登记不能代替视觉审核。
- `benchmarks/README.md` 的“其他画风验证”：记录 3.1 锚点获用户认可。
- `benchmarks/style-3.1/README.md` 的“2026-08-04 三阶段递进修正回归”：两张样图内部通过、待用户复核，并保留单次强修正改色的反例。
- `benchmarks/style-19/README.md`：文档首段明确“历史编号 19 / 当前 18”，只支持当前 18 的证据范围。

`documented-example` 表示有展示或示例登记；`internal-reviewed` 表示资料记录内部审核；`user-approved` 只适用于来源明确记录的对象；`not-recorded` 表示所述范围缺少足够记录。所有结论都保留来源范围。本次未重新看图验收，也没有把资料自述提升为新的独立验证。

结构测试仅检查字段、覆盖范围、编号关系和来源定位，不能判断自然语言主张是否得到来源支持。维护时仍须逐条阅读资料。当前 3.1 以专节和现行合同为准，历史纸质增强附录不能覆盖它的平面白底约束。
